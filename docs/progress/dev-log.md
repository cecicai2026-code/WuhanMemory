### 板块 2：景点数据和数据质量规则

- 在新分支 `block-2-poi-data` 上做。开工前 Claude 先讲了数据格式、列了 10 个景点的问题、给了填写模板，我确认了格式和过期时间。
- 文书里的三条规则落到字段上：每条信息都有 `verification`（实地核实、核对过来源、官网占位、TODO 四档）、`sourceId`（指向景点文件开头的来源列表）和 `lastCheckedAt`；会变的信息（开放时间、预约、票价、支付、交通、周边美食）还必须有 `expiresAt`，有效期有上限。"核对过来源"这一档是为节假日开放时间、预约规则这类在现场核实不了的信息加的。
- 开放时间写成结构化的时段（月份、星期、开门、关门、最晚入场），不是一段文字，因为板块 5 要让程序判断"到达时开没开门"。

### 板块 3：高德地图和路线

- 在新分支 `block-3-amap-routes` 上做。开工前 Claude 先讲了四件事：两种 key 放在哪、坐标系、缓存多久过期、调用限额够不够。
- key：浏览器只有 JS key。安全密钥和 Web 服务 key 只在后端。高德官方给了两种用安全密钥的办法，明文写进网页（官方说不建议在生产环境用）或者走自己的代理服务器（官方强烈建议），我们走代理：浏览器的地图请求先到后端的 `/_AMapService`，后端加上安全密钥再转给高德。
- 坐标：景点资料和高德都用 GCJ-02，不用转换。
- 限额：官方定价页写的是月配额，个人认证开发者路径规划等基础服务每月 15 万次。10 个景点两两之间三种方式一共 270 次就能填满缓存，总量足够；真正要小心的是每秒请求数，所以请求一个一个发、之间留间隔。
- 我用 Claude 写的临时脚本在终端验证了三个 key：Web 服务 key 步行、公交、驾车都返回 OK；JS key 加载出了地图；安全密钥让地点搜索返回了黄鹤楼。黄鹤楼到户部巷只有 699 米，公交那次没有方案，所以界面要能处理"没有公交方案"。
- 我选了：用高德官方加载器；配色先用自带的"幻影黑"；点图钉出跟着图钉的气泡卡片；缓存步行 30 天、公交地铁 7 天、驾车 1 天。驾车最短，因为驾车时间是查询那一刻的路况。
- 地图 provider 接口改成图钉、卡片、路线三类操作，页面不直接碰高德的对象，以后换地图只要新写一个实现。2D/3D 用同一张地图切换俯仰角，不用重建。
- 后端路线服务：先看 SQLite 缓存，没过期就直接用；过期了再问高德，查到的写回缓存，记 `checkedAt` 和 `expiresAt`；重查失败时先用旧结果，标"已过期"。公交统一按当天上午 10 点出发查，避免半夜查到地铁停运又被缓存一周。高德的原始返回也存下来，方便核对。

- 后端测试 77 个通过。前端类型检查只剩"找不到 `@amap/amap-jsapi-loader`"，要我装好这个包。

### 板块 4：千问和豆包真实接入与切换

- 在新分支 `block-4-llm-gateway` 上做。开工前 Claude 先讲了三件事：网关现在怎么工作、缺什么、两家接口哪里不一样。7 月的骨架只能在启动时定死一个模型，超时写死、没有重试，输出不是 JSON 时不报错而是把原文包一层当成功返回，而且没有任何代码在用它。
- 我用 Claude 写的临时脚本验证了两个 key 和豆包的接入点：千问 `qwen-plus` 约 0.6 秒；豆包的接入点对应的真实模型是 `doubao-seed-2-1-pro-260915`，默认开着深度思考，一次普通问答 5.9 秒，218 个输出 token 里 209 个是思考。两家都接受 JSON 输出模式。
- 我的选择都按 Claude 推荐的来：自动换备用模型默认关（悄悄换模型会让"这次用了哪个模型"说不清）；板块 5 之前在界面上加一个临时的"试一句"；调用记录存 SQLite，不存提示词和回答；超时 60 秒、最多重试 2 次；工具调用这次不做；mock 只留给测试。
- 分工：provider 只发一次请求、把对方的错误翻译成我们自己的错误类型；重试、等待、检查输出、让模型重答、记录都在网关里。这样网关的逻辑可以用一个假 provider 来测，不用联网。
- 输出修复：模型的输出不是 JSON 对象、被截断、或者字段不对时，把它上一次的输出和哪里不对一起发回去，让它重答一次；还不行就报"输出格式错"，不把坏数据交给业务代码。
- Claude 对着两家官方的错误码文档核了一遍。发现两家都把"额度用完"和"限流"报成同一个状态码 429，但额度用完再等也没用，所以多分出一种错误类型，不重试。
- 切换有三层：`.env` 里的默认模型；每次请求可以另外指定；界面上的模型选择用的就是"每次请求指定"。接口 `GET /api/llm/providers` 告诉前端有哪些模型、配没配置，不返回 key，也不返回豆包的接入点 ID。
- key 的保护：只出现在请求头里；错误信息引用对方返回的内容前先把 key 换成 `***`；这些都有测试。
- 冒烟测试我在终端跑了，两个模型都通过：千问 901 毫秒，豆包 2491 毫秒，都没有重试和修复。又临时关掉豆包的思考跑了一次，豆包 2064 毫秒，输出 token 从 35 降到 7。这条简单请求上差别不大，我决定豆包保持模型默认（开着思考），板块 5 有了真实的规划提示词再比。
- 遇到的问题：我把 `.env` 的默认模型从 mock 改成 qwen 之后，开着的后端还是认 mock，因为 `.env` 只在后端启动时读一次，要重启。
