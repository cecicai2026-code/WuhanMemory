# Frontend UX Architecture

## 页面结构

> 2026-11-15：按板块 1A 的实现更新。视觉和交互以 `docs/design/design-system.md` 为准。

每个页面是一"幕"，最外层都包 `components/shell/Scene.tsx`：左上是幕的编号和名称，右上是计数和菜单，左下是返回，右下是"开始规划"。不放传统导航栏。

| 路径 | 页面 | 板块 1A 做到哪 |
|---|---|---|
| `/` | 首页 | 标题和四个入口的普通网页版。桌面立体场景在板块 1B |
| `/map` | 地图工作台 | 左对话纸（板块 5）、中间灯箱里的高德地图（板块 3）、右行程卡（板块 5）。右上角标注当前模型和校验结果 |
| `/places` | 地点档案列表 | 数据来自 `GET /api/pois`；按区域筛选，筛选条件写在地址里；卡片上是景点状态章和待确认、待补充、已过期的条数 |
| `/places/[id]` | 景点详情 | 数据来自 `GET /api/pois/{id}`；四个主题是同一页上的四张信纸，用锚点跳转；每个条目下写核实方式、来源、核实日期和有效期，过期的把过期日期加粗；条目旁不盖章，每张纸右下角盖一个章（已核实、待确认或已过期）；四张纸上面有一行说明解释这三种状态；没有的条目显示"待补充" |
| `/compare` | 模型对比 | 空页面，板块 6 做 |
| `/trips` | 我的行程 | 空页面，板块 7 做 |
| `/s/[slug]` | 分享页 | 空页面，板块 7 做 |
| `/styleguide` | 样式参考 | 色板、字体和基础组件，不在菜单里，开发时对照用 |

普通网页版不是临时的：板块 1B 加上立体场景后，它仍是手机端、无障碍和立体场景加载失败时的版本。

`/map` 的三种宽度：

- 1068px 以上：三栏并排，整页不滚动，对话和行程各自在栏内滚动。
- 734 到 1067px：地图在上，对话和行程在下面并排。
- 734px 以下：地图在上，对话和行程在底部面板里用两个纸签切换，面板可以收起。

## 前端代码结构

- `app/globals.css`：设计规范的颜色、字体、字号、缓动，全部是 CSS 变量。改数值先改设计规范。
- `app/layout.tsx`：引入自托管的字体文件。
- `components/ui/`：基础组件，只管长相，不含业务数据。
- `components/shell/`：`Scene`（四角标注）、`Menu`（菜单）、`Blank`（空页面的信纸）。
- `lib/scenes.ts`：全部页面的编号、名称和路径，菜单从这里生成。
- `lib/places.ts`：景点数据的入口，在服务器端调用后端的 `GET /api/pois` 和 `GET /api/pois/{id}`（地址取 `API_BASE_URL`，没有就用 `NEXT_PUBLIC_API_BASE_URL`）。后端连不上时页面显示启动命令。
- `lib/format-poi.ts`：把开放时间、票价等结构化内容写成纸上的文字。
- `app/places/PlaceParts.tsx`：纸上的条目、来源和核实日期那一行、图册。
- `lib/map/amap-provider.ts`：高德地图 provider，实现 `packages/map-core` 的接口；`lib/map/amap-types.ts` 是用到的高德对象的类型。
- `app/map/MapPanel.tsx`：灯箱里的地图、图钉卡片、2D/3D 拨杆；`app/map/RouteFinder.tsx`：临时的"两点之间怎么走"；`app/map/ModelPicker.tsx`：模型选择（板块 4）。
- `app/map/ChatPaper.tsx`：对话纸、规划进度；`app/map/ItineraryCards.tsx`：行程卡；`app/map/PlannerState.tsx`：选中的模型和校验结果（右上角标注要用）；`lib/planning-client.ts`：对话和规划接口（板块 5）。
- 每个页面自己的组件和样式（CSS Modules）放在页面文件夹里，例如 `app/map/Workbench.tsx`。

## 地图交互

板块 3 已实现（2026-11-15）：

- 灯箱里是高德地图，配色"幻影黑"。打开时加载 10 个景点的图钉，自动缩放到正好框住全部景点。
- 图钉是黄铜圆头加一根针，悬停或键盘选中时显示名字。点图钉在它上方出现一张索引卡（名字、所在区、资料状态、"看地点档案 →"），选中的图钉变成樱桃红。按 Esc、点叉或点地图空白处关上。
- 灯箱旁的拨杆切换 2D / 3D。手机上默认 2D，拨杆压在灯箱右上角。
- 左边对话纸的输入横线上方是模型选择（板块 4）：千问和豆包各一张小签，选中的那张颜色变深、前面有一个勾；后端没配置 key 的那张是虚线框、选不了，写着"没配置"。清单从 `GET /api/llm/providers` 取，上次选的记在浏览器里。选中的模型跟着每条消息发给后端（板块 5），规划中不能换。
- 右边索引卡最上面是临时的"两点之间怎么走"：选两个景点，并排看三种方式的时间、距离、费用、查询和过期时间；点"在地图上看"把那条路线画在地图上，并缩放到这条路线。步行是纸色虚线，公交地铁是黄铜色，驾车是胶片橙。
- 没有 JS key、地图脚本加载失败、后端没启动、高德报错时，灯箱或卡片上用文字说明原因和怎么办。底图 15 秒还没画完时提示"加载得比较慢"，但继续等。
- 框住景点和路线时按墨卡托投影自己算带小数的缩放级别（高德的 `setBounds` 只给整数级，框得偏松）。

板块 5 已实现（2026-11-15）：

- 有行程时，地图上只放这一天的景点，图钉名字前加顺序（"1 · 黄鹤楼"），画出这一天每段交通的折线（颜色按交通方式，和"两点之间怎么走"一样）；多天的行程用行程卡上的"地图上看 第 N 天"切换。没通过校验的行程不画。
- "全部"（2026-11-15 Cecilia 要加的）：画出每一天的路线，按天分色（黄铜、纸色、胶片橙轮换，`app/map/day-colors.ts`），交通方式只用线型区分（步行虚线）；图钉写"1-2 · 黄鹤楼"（第 1 天第 2 站）；"地图上看"下面列出每天的颜色。颜色名由页面给（`MapRoute.color`），色值由地图 provider 对着设计规范取。
- "地图上看"和图例在桌面上、不在纸上，所以文字用桌面的次要文字色。

## 对话和行程卡（板块 5）

- 对话纸：用户的话加粗，回复是纸上正文，下面标着用的模型；反问、行程、未通过、出错四种回复，未通过和出错是红褐色字。发送后显示"规划中 · N 秒"和链路真的走过的步骤（后端报一步显示一步，不预先画出没发生的步骤）。对话 id 记在浏览器里，刷新后接着显示；"新对话"清掉对话和行程。
- 行程总卡：校验结果的印章（绿色"校验通过"、蓝灰色"有警告"、红色"未通过"），模型和真实模型名，是否修正过，按默认补的设置，错误清单，警告清单（多于 4 条时折起来）。下面一行说明"待确认"是什么意思。
- 每天一张卡：日期和星期（未定时写"日期未定"）、主题、右上角这一天的印章；时间线上每站是时间、景点名（链接到地点档案）、理由、开放、预约、门票、支付（旁边标待确认、待补充、已过期），和这一站有关的问题；两站之间是交通（方式、分钟数、距离、费用、线路、为什么选这种方式、高德查询日期）和交通的问题。
- 未通过的行程只显示总卡（问题清单），不显示时间线。
- 右上角的四角标注：当前模型和当前行程的校验结果。
- 手机上：排好后自动切到"行程"纸签。


## 对话体验（早期设想，现在的样子见上一节）

- 输入框支持自然语言。
- AI 不确定时先补问关键缺失信息。
- 规划中展示阶段状态:
  - 理解偏好
  - 搜索景点
  - 计算路线
  - 校验开放时间
  - 生成地图行程
- 失败时展示可恢复操作，例如重试、减少约束、切换交通方式。

## 行程时间线（早期设想，现在的样子见"对话和行程卡"）

每个 item 展示:

- 时间段。
- 景点或交通类型。
- 名称。
- 推荐理由。
- 预计停留时间。
- 交通方式、耗时和费用。
- 预约、门票和支付提示。

## 景点详情

详情面板包括:

- 简介。
- 历史文化。
- 评价摘要。
- 拍照机位。
- 适合人群和避坑提醒。
- 开放时间、票务、预约方式。
- 到达方式和附近推荐。
- 来源和更新时间。

## 设计原则

- 工作台以好用为先：清晰、可扫描，不加装饰性动效。
- 地图和时间线优先，物件不遮挡地图和文字。
- 控件带文字标签，状态不只靠颜色区分。
- 重要状态有 loading、empty、error、retry。
- 移动端文本不能遮挡地图核心点位。

## 前端状态划分

- Server state: conversation、planning job、itinerary、share page。
- Client state: 当前地图模式、当前天、选中 POI、打开的面板、路线动画状态。
- Persisted local state: 匿名 session id、最近城市、用户偏好草稿。

## 可访问性

- 地图信息必须在时间线中有文本等价展示。
- 所有按钮和图标有 accessible label。
- 色彩不能是区分路线的唯一手段，还需要 day label 或 marker 编号。
- 键盘可操作对话输入、每日切换和详情面板关闭。
