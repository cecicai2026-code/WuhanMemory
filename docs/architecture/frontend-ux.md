# Frontend UX Architecture

## 页面结构

> 2026-11-14：页面结构已调整，以 `docs/design/design-system.md` 第 2 节为准。首页 `/` 改为滚动叙事的展示页，规划工作台移到 `/map`。本文件其余内容在板块 1 同步更新。

### `/map`（原 `/`）

规划工作台。首屏即为可用界面:

- 左侧或底部 AI 对话面板。
- 主区域地图。
- 右侧或抽屉显示行程时间线和景点详情。
- 移动端采用地图全屏 + 底部 sheet。

### `/itineraries/{id}`

可编辑行程页:

- 版本切换。
- 按天筛选。
- 锁定、删除、替换景点。
- 对话式修改。

### `/s/{slug}`

只读分享页:

- 行程标题、日期、每日路线。
- 地图点位和路线。
- 景点详情、拍照机位、交通和支付提示。
- 来源和更新时间。

## 地图交互

- 2D/3D 切换按钮固定在地图工具栏。
- 按天切换路线，不同天使用稳定但克制的颜色。
- 点击 POI marker 打开景点详情。
- 点击交通段显示交通方式、耗时、距离和费用估算。
- 支持 `fitBounds` 自动聚焦当前天路线。
- 规划生成时地图逐步展示候选 POI、确认路线和最终行程。

## 对话体验

- 输入框支持自然语言。
- AI 不确定时先补问关键缺失信息。
- 规划中展示阶段状态:
  - 理解偏好
  - 搜索景点
  - 计算路线
  - 校验开放时间
  - 生成地图行程
- 失败时展示可恢复操作，例如重试、减少约束、切换交通方式。

## 行程时间线

每个 item 展示:

- 时间段。
- 景点或交通类型。
- 名称。
- 推荐理由。
- 预计停留时间。
- 交通方式、耗时和费用。
- 预约、门票和支付提示。

## 景点详情

详情面板包括:

- 简介。
- 历史文化。
- 评价摘要。
- 拍照机位。
- 适合人群和避坑提醒。
- 开放时间、票务、预约方式。
- 到达方式和附近推荐。
- 来源和更新时间。

## 设计原则

- 工作台风格应克制、清晰、可扫描。
- 地图和时间线优先，不做营销式 landing page。
- 控件使用清晰图标和 tooltip。
- 重要状态有 loading、empty、error、retry。
- 移动端文本不能遮挡地图核心点位。

## 前端状态划分

- Server state: conversation、planning job、itinerary、share page。
- Client state: 当前地图模式、当前天、选中 POI、打开的面板、路线动画状态。
- Persisted local state: 匿名 session id、最近城市、用户偏好草稿。

## 可访问性

- 地图信息必须在时间线中有文本等价展示。
- 所有按钮和图标有 accessible label。
- 色彩不能是区分路线的唯一手段，还需要 day label 或 marker 编号。
- 键盘可操作对话输入、每日切换和详情面板关闭。
