# ADR 0009: 中英双语：同一个网址、语言记在 cookie；景点资料用带原文的译文文件

日期: 2026-11-15

## 状态

Accepted（Cecilia 2026-11-15 定：覆盖范围、网址方式、按钮样式、默认语言都选了推荐的做法）。

## 背景

Cecilia 要求网站出一个中英双语版本，右上角一个按钮切换。原来全站只有中文：界面文字写在前端约 77 个文件里，10 个景点的资料只有中文，后端的反问、校验说明、对比表、出错提示和模型写的理由也都是中文。

## 决定

1. **覆盖范围**：界面、景点资料、AI 规划都有英文。
2. **网址不变，语言记在 cookie `wm-lang`**。第一次来、还没点过切换时按浏览器的首选语言猜：首选是中文就中文，其他都是英文。不改目录结构，立体场景的 layout 和三幕共用的引擎不受影响。
3. **切换按钮**：右上角菜单旁边一块黄铜铭牌"中 / EN"，当前语言亮。每一页都在，手机上也在（手机上菜单只留三条横线图标，字给读屏软件）。
4. **前端写法**：中英两句写在一起，`t("中文", "English")`。服务器组件用 `lib/i18n-server.ts` 的 `getT()`，浏览器组件用 `useT()`，两边都能用的小组件用 `<Tr zh en />`。不用"键名 → 字典"，改文案时两种语言都在眼前。
5. **前端怎么告诉后端**：服务器端取数据带 `?lang=`，浏览器里调接口带请求头 `X-Lang`，经网站转发的请求也带着 cookie。后端按 `?lang` → `X-Lang` → cookie 的顺序认，都没有就是中文（`app/core/lang.py`）。
6. **后端写法**：规划、对比链路很长，语言放在 contextvar 里：`LangMiddleware` 每个请求开始时设好，规划和对比的后台任务用发起请求时的语言跑（`run_in_lang`）。写给人看的话一律 `L("中文", "English")`。给模型看的提示词仍是中文规则，英文时只在系统提示词后加一句"title、theme、reason 用英文写"，两个模型看到的是同一套规则。
7. **逻辑不随语言变**：候选、兴趣、侧重规则（5A、文化类标签）、点名必去的匹配都按中文资料判断；点名匹配另外认英文名。英文只是换说法。
8. **景点资料的英文是译文**，放在 `data/pois/en/<id>.json`，每条存着翻译时的中文原文：中文资料改了、和原文对不上，这条译文就作废，英文版显示中文，数据检查报 `translation-stale` 警告。所以译文不会和中文资料说的不一样。只翻界面上会显示的字段（`app/services/poi_i18n.py` 的 `TRANSLATABLE`）；来源网页的标题按引用的规矩保留原文，核实备注和 TODO 是给 Cecilia 看的，不翻。现在 10 个景点的译文由 Claude 翻译，**未经人工核对**，界面上状态说明那一行写明了这一点。
9. **存下的记录按生成时的语言**：行程版本、对话消息、对比结果是生成时的语言，以后不再翻译。侧重名、步骤名、方案对比表这些读的时候现算的部分跟着当前语言。路线缓存里存中文，读出来时把线路名和固定说法换成英文。

## 没选的做法

- 网址带 `/en/` 前缀：链接本身带语言、搜索引擎能分别收录，但要把整个 app 目录挪进 `[lang]` 一层，立体三幕共用引擎的 layout 也得挪，改动大。分享链接现在不带语言，打开的人看到的是自己选的语言（分享页的行程内容是生成时的语言）。
- 只翻界面文字：最快，但英文用户看不懂景点资料和 AI 的结果。
- 景点资料在请求时现场交给模型翻译：每次都花额度、结果每次不同，也没法检查。
- 把译文直接写进中文资料文件的新字段：中文改了以后看不出译文过时。

## 已知限制

- 高德 JS API 2.0 的地图底图只有中文地名：2026-11-15 在浏览器里试过 `lang: "en"`，默认样式和深色样式都不起作用。
- 高德返回的公交线路名只换了"轨道交通 N 号线"和"N 路"两种格式，其他名字（例如有轨电车）保持中文。
- 换语言时立体场景会重搭（物件上的字是画在贴图里的），镜头回到这一幕的起点。
