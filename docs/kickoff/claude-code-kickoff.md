## 1. 项目是什么（我最初的需求）

一个基于地图、可以切换 2D / 3D 的武汉旅游 AI 规划网页应用。
用户在 AI 对话框里说想去武汉、喜好、具体时间，系统就规划行程。行程包含路线、景点信息、交通工具、支付方式等。
每个景点能显示多媒体介绍、评价、历史文化、拍照机位。
规划结果在地图上动态展示，还能生成一个可分享的行程网页。
大模型用豆包和通义千问（Qwen），两个都支持，可以切换。
系统框架和项目进度要记录在本地文件里，方便下次接着做。

## 5. 设计方向（界面风格）

2026-11-14 改过几次，现在是第三版。完整规范见 `docs/design/design-system.md`，以那份文件为准。要点：

- 风格："暗房桌面"。整个网站是暗房里的一张木桌，每个页面是桌上的一个场景。依据是我提供的三张参考图（胶卷和看片器、晾片绳和显影盘、桌上的信纸）。
- 颜色和光：黑、红褐色木头、墨绿器物、黄铜、米黄色的纸；一盏暖色的灯，四周是暗角。
- 字体：四种字各有分工，等宽小字做标注，衬线字做标题，打字机字写纸上的正文，手写字做批注。
- 界面做成实物：按钮是黄铜铭牌，卡片是信纸和索引卡，状态是印章。
- 交互：鼠标悬停有反应，点击才进入，不用拖拽。动效要丝滑、有重量。
- 地点档案分三幕：胶卷（滚动看全部景点）→ 晾片（一个景点，盘子里是四个主题：景点概览、游玩建议、景点图册、周边美食）→ 纸页（一个主题的内容）。
- 只参考手法，不照搬参考图和参考网站里的具体物件、文字和图片。

页面：**首页**（`/`，桌面全景）、**地图**（`/map`，灯箱里的地图工作台 + AI 对话）、**地点档案**（`/places`）、**模型对比**（`/compare`）、**我的行程**（`/trips`）。

注意：文书里讲的核心功能在地图工作台。地图工作台打开就要能用，不需要滚动，也不加装饰性动效。手机上也要能用。

## 6. 技术决定（已定，除非我改主意）

- 前端 Next.js App Router + TypeScript；后端 FastAPI + Python。
- 地图：高德 JS API 2.0，`viewMode: '3D'` 加俯仰角实现 2D/3D 切换；路线用高德 Web 服务，由后端调用。
- 数据库：我电脑没装 Docker。先用 **JSON 种子文件 + SQLite**，零安装。数据访问写成 repository 层，以后可以换 PostgreSQL/PostGIS。需要为这个改动写一条 ADR，替换原来"PostgreSQL + PostGIS"的决定。
- 模型：通义千问（阿里云百炼）和豆包（火山方舟），都走 OpenAI 兼容接口，经过 `LLMGateway`。

### 板块 5：AI 规划链路和行程校验（核心）

**目标**：用户说一句话，得到一份经过校验的逐日行程，显示在地图上。

**要做的事**
1. 对话界面：输入需求，显示规划进度。
2. 抽取偏好：天数、日期、节奏、兴趣、预算、同行人、交通偏好。信息不够时反问用户。
3. 从景点库筛候选。AI 只能从候选里选，不能自己造景点。
4. 模型按固定结构输出行程。
5. `validate_itinerary` 校验：景点存在于数据库；到达时间在开放时间内；相邻景点留够交通时间且不重叠；每天总时长合理；用到过期数据给警告。
6. 校验失败时把错误交给模型修正一次；还不行就明确告诉用户，不展示不合格的行程。
7. 行程面板：逐日时间线、每段交通方式和时间、每个景点的支付和预约提示；地图上同步显示。
8. 界面显示校验结果和所用模型。
9. 给校验写单元测试：闭馆、时间冲突、景点不存在、数据过期。

**需要我做的事**：在终端启动前后端，试几条真实请求，截图。
